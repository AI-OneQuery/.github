### 흩어진 API를 자연어 질문 하나로

여러 시스템에 나뉘어 있는 데이터를, AI 에이전트가 필요한 것을 스스로 찾아<br/>
가져와 합치고 보고서까지 만들어 주는 대화형 데이터 활용 플랫폼입니다.

## 무엇을 푸는가

서비스가 늘어날수록 데이터는 시스템마다 쪼개집니다. 질문 하나에 여러 부서를 거쳐
며칠이 걸리고, 개발자는 같은 형태의 추출 요청에 매주 시간을 씁니다. 실무자는 컬럼명과
코드 체계가 제각각인 파일을 손으로 맞추다가 누락과 중복을 반복합니다.

**데이터를 한곳에 모으는 대신, 각 서비스가 이미 제공하는 인터페이스(OpenAPI/Swagger)를
AI가 쓸 수 있는 도구로 자동 전환합니다.** 원천 서비스는 코드 한 줄 바꾸지 않습니다.

```
Swagger 주소 등록  →  기능 자동 수집·분류·색인
                          ↓
자연어 질문        →  필요한 기능 선택·실행  →  여러 시스템 데이터 병합
                          ↓
                     엑셀 · 보고서 · 차트
```

## 어떻게 동작하는가

| 단계 | 하는 일 |
|---|---|
| **수집** | 등록된 Swagger 문서를 읽어 오퍼레이션 단위로 분해합니다 |
| **분류** | 각 기능이 조회인지 변경인지 판정해 정책 등급을 매깁니다 |
| **색인** | 자연어로 찾을 수 있도록 기능 설명을 임베딩해 검색 가능한 형태로 둡니다 |
| **계획** | 질문을 읽고 어떤 기능을 어떤 순서로 부를지 에이전트가 정합니다 |
| **실행** | 페이지네이션·기간 분할·인증을 처리하며 데이터를 모읍니다 |
| **집계** | 모인 데이터를 합쳐 답변과 산출물을 만듭니다 |

**변경 계열 기능은 사람이 승인하기 전에는 실행되지 않습니다.** 조회는 자동, 변경은
승인, 금지는 차단 — 이 구분이 시스템 전체를 관통하는 원칙입니다.

## 저장소

이 조직의 저장소는 **모두 비공개**입니다. 다루는 주제의 성격상 시스템 주소나
접속 정보가 밖으로 나가지 않도록 처음부터 비공개로 두고 작업했습니다.

| 저장소 | 내용 |
|---|---|
| `OneQuery_Submission` | 제출본 |
| `OneQuery_FULL` | 전체 아카이브 — 기획 문서 · 백엔드 · 프론트엔드 · 목 서비스 |
| `OneQuery_BE` · `OneQuery_FE` | 용도별로 나눈 사본 |
| `OneQuery_swagger` | 개발·검증용 테스트 서버 |
